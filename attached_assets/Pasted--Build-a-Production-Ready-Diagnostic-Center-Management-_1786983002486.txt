# Build a Production-Ready Diagnostic Center Management & Appointment System

Build a modern, responsive, production-ready web application for a diagnostic center to manage patients, appointments, tests, packages, labs, slots, payments, reports, users, notifications, WhatsApp communication and analytics.

This is NOT a simple appointment booking website.

It should be an internal operational platform similar to a lightweight diagnostic-center CRM/LIS appointment management system.

The application must be designed with scalability, security, real-time updates, role-based access control, audit logging and future multi-branch support in mind.

---

# 1. Recommended Technology Stack

Use a modern full-stack architecture.

Preferred stack:

* Frontend: React / Next.js
* UI: Tailwind CSS
* Component library: shadcn/ui or an equivalent modern component library
* Backend: Node.js with Express OR Next.js API routes
* Database: PostgreSQL
* ORM: Prisma
* Authentication: Secure session/JWT based authentication
* Real-time updates: WebSockets / Socket.IO / Supabase Realtime
* File storage: S3-compatible storage
* Charts: Recharts or equivalent
* Validation: Zod
* Password hashing: bcrypt/argon2
* API documentation: OpenAPI/Swagger if practical

Use TypeScript throughout the application.

If Replit's environment makes another equivalent technology more practical, maintain the same architecture and functionality.

Do NOT use mock data as the final implementation.

Create a proper PostgreSQL database schema and migrations.

# 11. Prevent Double Booking

This is mandatory.

The backend/database must prevent two users from booking the same available capacity simultaneously.

Do NOT depend only on frontend checks.

Use database transactions and appropriate constraints/locking.

Example:

If slot capacity = 2 and two users attempt booking simultaneously:

Only two appointments may succeed.

The third request must receive:

"Slot no longer available."

# 36. Real-Time Conflict Handling

If two users edit the same appointment:

The application should detect stale data/version conflicts.

Do not silently overwrite changes.

Use optimistic locking/version numbers or another appropriate concurrency mechanism.

Display:

"This appointment was updated by another user. Please refresh the latest information before saving."
